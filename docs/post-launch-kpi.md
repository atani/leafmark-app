# Post-Launch KPI 記録

`/apple-post-launch` の月次レビュー用ベースライン。数値は App Store Connect Analytics。

## 🔴 訂正（2026-07-26）: 以下の「単日」ベースラインはすべて 30 日累計の誤読

Analytics の概要タイルは日付ラベル（例「July24日」）が付くが、値は**その日を末尾とする 30 日累計**。
過去の 7/13・7/19 ベースラインはこれを単日値として読んだため、規模を約 30 倍に過大評価していた。

2026-07-25 に期間 Jun25–Jul24 で実測した結果を次に示す。

| 指標 | 概要タイル | メトリックス 30 日合計 | 判定 |
|---|---:|---:|---|
| プロダクトページ閲覧数 | 125 | 125 | 一致 |
| アプリ内購入数 | 1 | 1 | 一致 |
| 収益 | $8 | $8 | 一致 |
| 初回ダウンロード数 | 40 | 40 | 一致 |

決定的証拠: タイルはアプリ内購入 1 件を表示するが、時系列の 7/24 行は `-`（0）。
唯一の購入は **7/8 の 1 件**。つまりタイルは単日値ではなく期間合計。

### 実際の状況（Jun25–Jul24 の 30 日間）

| 指標 | 値 | 日次換算 |
|---|---:|---:|
| インプレッション | 1,000 | 約 33/日 |
| プロダクトページ閲覧 | 125 | 約 4/日 |
| 初回ダウンロード | 40 | 約 1.3/日 |
| アプリ内購入 | 1 | 0.03/日 |
| 収益 | $8 | — |

ローンチ（6/27）以降の販売本数は実質 **1 本**。購入 n=1 では転換率・価格・Paywall の
良し悪しは統計的に判定できない。

## 🔴 追記（2026-07-26）: この期間はアプリが正常に読めない状態だった

上の数字を「露出が律速」と読んでいたが、それ以前の問題があった。

MobileRead のスレッドで 2 名が同じ症状を「アプリが使えない」と報告していた。
ページを送ると次ページの先頭行が現在のページに重なる、という描画の不具合である。
App Store の 1 つ星（v1.8）も同じ症状を指していた。

原因は `ReaderView.swift` で Readium の `contentInset` を上下 20pt に縮めていたこと。
この余白は段組みをページ境界で終わらせるための予約領域だった。
縮小は issue #20 対策として `96b20a0`（2026-07-10）で入り、**v1.6 以降の全バージョンに含まれる**。
v1.6 のリリースは 7/13 で、上のベースライン期間とほぼ完全に重なる。

つまり、計測期間のほぼ全体で「本が正常に読めない」状態だった。
したがって次の解釈はいずれも成り立たない。

- 「露出が律速」: 露出を増やしても、来た人が読めなければ転換しない
- 「ストアページは刺さっている（CV 11.4%）」: ダウンロードまでは正しいが、その先で失われていた
- 「価格や Paywall の妥当性」: 判定材料にならない

**露出施策の効果を測る前に、修正版（1.10 build 17）が届いた後の期間でベースラインを取り直す。
それまでの数値は product-market fit の判断に使わない。**

縦のはみ出しを直した版は v1.10 として 2026-07-25 23:47 UTC に配信した。続く v1.11 は
2026-07-27 07:24 UTC。いずれも App Store のバージョン履歴で確認した
（`https://apps.apple.com/us/app/id6781045740`）。

### 🔴 追記（2026-07-29）: 同じ「2 ページ分見える」症状がもう 1 件あり、v1.11 でも直っていない

v1.10 で直したのは**縦方向**のはみ出しだった。読者が報告していたのはもう 1 つ、
**横方向**のずれである。段間（`--RS__colGap`）を 30px にしていたため、
1 ページ送るごとに本文が段間ぶん先へ行き、ずれが累積して 1 画面に 2 ページ分が
並ぶ。章が変わるとリセットされ、読み進めるとまた出る。

- 出所: MobileRead t=374295 post #37（The Old Man 氏、iPad mini・iPhone 16・
  iPad Pro 11 インチ、スクリーンショット付き）
- App Store の 1 つ星レビューは **v1.10 に対するもの**で、投稿は 2026-07-26 09:51 UTC。
  つまり縦の修正が届いた後も症状は残っていた
- 修正は [#40](https://github.com/atani/epub-reader-ios/pull/40)。iPad Pro 13 インチで
  1 ページごとに約 60px ずれることを実測し、段間 0 で止まることを確認した

**したがってベースラインの取り直しは 7/26 起点では成立しない。#40 を含む版が
配信された日を起点に取り直す。それまでの数値は判断に使わない。**

#40 を含む v1.12（build 19）は 2026-07-29 21:18 UTC に配信された。
**取り直しの起点は 2026-07-30（UTC の初日）とし、Jul30–Aug28 の 30 日を
2026-08-29 に計測する。** ローンチから 1 か月あまり、読める状態で計測できるのは
これが初めてになる。

なお v1.10 のリリースノートは無料エクスポート・縦書き・共有シートのクラッシュ修正
だけに触れており、縦のはみ出しの修正に言及していない。症状を報告した読者には、
何が直って何が残っていたのかが届いていなかった。

単体テストは 135 件すべて通っていたが、描画の崩れは捕まらなかった。
リリース前に同梱サンプルを数ページ送って表示を目視する手順を `release-checklist.md` に追加する。

## ベースライン: 2026-07-19（v1.8 リリース日）※値は 30 日累計（当時は単日と誤読）

| 指標 | 値 | メモ |
|---|---|---|
| 初回ダウンロード | 38 | |

| コンバージョン率 | 11.9% | 日次平均 |
| インプレッション | 837 | |
| プロダクトページ閲覧 | 101 | |
| アップデート数 | 95 | |
| 収益 | $8 | |
| アプリ内購入数 | 1 | |
| 7日目の有料版CV | 2.22% | |
| クラッシュ | データ不足（≒ゼロ） | |

### 読み（7/13 ベースライン比）

- 露出系（インプレッション +25%・初回DL +19%・プロダクトページ閲覧 +19%・CV率 11.9%で横ばい〜微増）はすべて伸びており、露出不足が購入停滞の原因ではない
- 収益・購入数は $8 / 1 件のまま変わらず、7 日目有料転換は 3.57% → 2.22%。**ただし母数が日次 30〜40 DL・7 日目転換の分子はどちらも 1 件のみで、% の変動はノイズの範囲**。「悪化」と断定できる規模のサンプルではない
- コード確認済み（`Sources/StoreManager.swift`）: 無料枠はハイライト 3 件/冊、統計・エクスポートは即 Pro 限定。以前疑った「無料枠が緩すぎて Paywall に到達しない」説は否定できる（枠はむしろ狭い）
- アプリ内に Paywall 表示・購入試行のイベント計装は無い（`Sources/PaywallView.swift` の表示トリガー3箇所にログなし）。Paywall 到達率・到達後離脱率が見えないのは事実だが、現状のサンプル数では計装を急ぐ根拠も弱い。露出チャネル拡大を継続しつつ、母数が積み上がってから再判定する
